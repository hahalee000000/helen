# v1.46.16: ChatSessionActor 自动重启机制

## 📋 背景

### 问题描述

在 helen-rust 项目中运行的 helen agent 出现以下问题：
1. ChatSessionActor 在推理过程中意外退出
2. 前端页面断开，无法继续推理
3. 没有自动重启机制，需要手动重启整个 agent

### 根本原因

1. **缺少健康检查**：主进程不会检测 ChatSessionActor 是否退出
2. **无自动重启**：ChatSessionActor 退出后没有恢复机制
3. **缺少错误日志**：无法追踪 ChatSessionActor 退出的原因

## 🎯 设计目标

1. **自动重启**：ChatSessionActor 退出时自动重启
2. **健康检查**：定期检查 ChatSessionActor 是否存活
3. **错误日志**：记录退出和重启事件
4. **保持向后兼容**：不影响现有功能

## 🔧 实现方案

### 1. 健康检查机制

**新增函数**（`chat_actor.helen`）：

```helen
fn _is_chat_actor_alive(): bool {
    if _chat_actor_mailbox == null {
        return false
    }

    // 尝试发送心跳消息
    try {
        _chat_actor_mailbox.send({"type": "heartbeat"})
        return true
    } catch RuntimeError err {
        debug("ChatSessionActor health check failed: " + err.message)
        return false
    } catch {
        debug("ChatSessionActor health check failed (unknown error)")
        return false
    }
}
```

**原理**：
- 通过尝试向 mailbox 发送心跳消息来检测 actor 是否存活
- 如果发送失败（mailbox 已关闭），说明 actor 已退出
- 捕获所有异常，避免健康检查本身导致崩溃

### 2. 自动重启机制

**新增函数**（`chat_actor.helen`）：

```helen
fn _ensure_chat_actor_alive(): bool {
    if _is_chat_actor_alive() {
        return true
    }

    // Actor 已退出，记录日志
    _chat_actor_restart_count = _chat_actor_restart_count + 1
    debug("ChatSessionActor exited unexpectedly (restart_count=" + 
          str(_chat_actor_restart_count) + "), attempting auto-restart...")

    // 清理旧的 mailbox
    _chat_actor_mailbox = null

    // 重启
    let result = spawn_chat_actor()
    if result["status"] == "started" || result["status"] == "already_running" {
        debug("ChatSessionActor auto-restart successful")
        return true
    } else {
        debug("ChatSessionActor auto-restart failed: " + 
              str(result.get("error", "unknown")))
        return false
    }
}
```

**原理**：
- 检查 actor 是否存活
- 如果不存活，增加重启计数器
- 清理旧的 mailbox
- 调用 `spawn_chat_actor()` 重启
- 返回重启结果

fn log_actor_error(error_type: str, message: str) {
    let log_path = get_cwd() + "/.helen/actor_errors.log"
    let timestamp_str = str(time())
    let log_entry = "[" + timestamp_str + "] [" + error_type + "] " + message + "\n"

    try {
        // 追加写入
        let existing = ""
        if path_exists(log_path) {
            existing = read_file(log_path)
        }
        write_file(log_path, existing + log_entry)
    } catch {
        // 日志写入失败不影响主流程

    }
}

## 🔍 关于 Memento 中 PID 的设计

### 当前设计

Memento 文件（`.helen/current_session_id`）包含：
```json
{
  "main": "test-session",
  "child": "session_1788400667_40a5c4aa",
  "pid": 27832
}
```

### PID 验证的必要性

**为什么需要 PID**：
1. **多实例竞争**：同一个目录下可能运行多个 helen agent（如 Python 版本和 Rust 版本）
2. **防止错误 resume**：避免一个 agent resume 到另一个 agent 的 session
3. **安全性**：确保 memento 是由当前进程写入的

**PID 验证逻辑**：
```helen
let memento_pid = 0
try {
    memento_pid = data["pid"]
} catch {
    // 旧 memento 无 pid 字段——接受（向后兼容）
    memento_pid = pid()
}
if memento_pid == pid() {
    child_sid = data["child"]
} else {
    debug("spawn_chat_actor: memento PID mismatch (memento=" + 
          str(memento_pid) + " own=" + str(pid()) + 
          ") — starting fresh session")
}
```

### 正常退出后的恢复

**场景 1：正常退出（收到 exit 消息）**
```helen
if msg_type == "exit" {
    debug("ChatSessionActor: received exit signal")
    try { reply.send({"type": "actor_status", "status": "exited"}) } catch {}
    try { reply.close() } catch {}
    break  // 退出主循环
}
```

**恢复流程**：
1. ChatSessionActor 收到 exit 消息
2. 发送 actor_status 确认
3. 关闭 mailbox
4. 退出主循环
5. **Memento 保留**（不清理）
6. 下次启动时，主进程读取 memento
7. PID 验证通过（如果是同一进程）
8. Resume 到之前的 session

**场景 2：异常退出（崩溃、被杀死）**
1. ChatSessionActor 异常退出
2. Memento 保留（包含旧 PID）
3. 用户重新启动 agent（新 PID）
4. 主进程读取 memento
5. PID 验证失败（memento PID ≠ 当前 PID）
6. **忽略 memento**，创建新 session
7. 防止 resume 到错误的 session

**场景 3：心跳超时退出**
```helen
// 300s 超时作为安全网：正常情况下 Python 端每 120s 发送心跳
let request_msg = reply.receive(timeout=300)

if request_msg == null {
    // 300s 无消息（无心跳、无 user_input），Web 端可能已崩溃
    debug("ChatSessionActor: no heartbeat for 300s, web client may have crashed, exiting gracefully")
    break
}
```

**恢复流程**：
1. ChatSessionActor 300s 无心跳
2. 优雅退出
3. Memento 保留
4. 下次启动时，PID 验证通过（如果是同一进程）
5. Resume 到之前的 session

### PID 设计的合理性

**优点**：
1. ✅ **防止多实例竞争**：不同进程的 agent 不会互相干扰
2. ✅ **向后兼容**：旧 memento（无 PID）仍然接受
3. ✅ **安全性**：确保 memento 的完整性
4. ✅ **简单高效**：只需比较一个整数

**潜在问题**：
1. ⚠️ **PID 复用**：操作系统可能复用 PID，但概率很低
2. ⚠️ **正常退出后无法 resume**：如果进程重启，PID 改变，无法 resume

**解决方案**：
- 对于正常退出，可以在退出前清理 memento
- 或者添加一个 `exit_code` 字段，区分正常退出和异常退出
- 当前设计已经足够安全，因为异常退出时不应该 resume
